Most Bootstrap 5 themes override Sass variables before they import Bootstrap. Most of those variables are gone in v6. Components read CSS custom properties (tokens) instead, and Sass maps that you can configure declare them. This page lists every `!default` variable from v5.3.9 and what replaces it. The [migration guide]([[docsref:/guides/migration]]) explains the reasons for these changes.

## Reading the tables

The **v6** column has one of these forms:

- **`$name`**: still a Sass variable. Pass it through `@use … with ()`. Some defaults changed, so read the notes.
- **`--name` in `$map`**: a token. Set it through that token map or in your own CSS.
- **`--name` (set on `.selector`)**: a token that a modifier class sets. Override it on that class.
- **`--name` (not declared)**: a token that no map declares. Set it in your own CSS. The note gives the value used when it is not set.
- **`$map: key`**: a key of a Sass map, such as `$theme-colors`, `$font-sizes` or `$zindex-levels`.
- **Removed**: no direct replacement. When something is close, the column names it. The notes say how it is different.

Token maps and most other maps merge your keys over the defaults. See [Token defaults]([[docsref:/customize/sass#token-defaults]]). The notes tell you when you must pass the whole map.

Token names have no prefix in the Sass source. Bootstrap’s compiled CSS adds the `--bs-` prefix with PostCSS. When you compile the source yourself, the names keep no prefix unless you add the same step.

```scss
@use "bootstrap/scss/bootstrap" with (
  // v5: $btn-font-weight: 600;
  $button-tokens: (
    --btn-font-weight: 600,
  ),
  // v5: $input-btn-padding-y: .5rem;
  $root-tokens: (
    --btn-input-padding-y: .5rem,
  ),
);
```

You can also set a token at runtime. Set a component token on the component class, not on `:root`, because the class declares its own value. See [Runtime overrides]([[docsref:/customize/sass#runtime-overrides]]).

```css
/* Your own build from the Sass source */
.checkout .btn {
  --btn-font-weight: 600;
}

/* Bootstrap’s compiled CSS */
.checkout .btn {
  --bs-btn-font-weight: 600;
}
```

## Dark mode variables

The v5 `*-dark` variables are gone. Most colors are now one `light-dark()` value: the light value first, the dark value second. See [Color modes]([[docsref:/customize/color-modes]]). To change only the dark value, write the full `light-dark()` value again with your dark color.

## Brand colors

In v5, `$primary: #0057c2` was enough. Sass derived the subtle backgrounds, borders and emphasis colors from it. In v6, each theme color is a map of roles: `base`, `fg`, `fg-emphasis`, `bg`, `bg-subtle`, `bg-muted`, `border`, `focus-ring` and `contrast`. The roles use the palette steps of one hue. Add your brand as a palette color to generate its steps. Then point the roles of the theme color at them:

```scss
@use "bootstrap/scss/bootstrap" with (
  $colors: (
    "brand": #0057c2,
  ),
  $theme-colors: (
    "primary": (
      "base": var(--brand-500),
      "fg": light-dark(var(--brand-600), var(--brand-400)),
      "fg-emphasis": light-dark(var(--brand-800), var(--brand-200)),
      "bg": var(--brand-500),
      "bg-subtle": light-dark(var(--brand-100), var(--brand-900)),
      "bg-muted": light-dark(var(--brand-200), var(--brand-800)),
      "border": light-dark(var(--brand-300), var(--brand-600)),
      "focus-ring": light-dark(color-mix(in oklch, var(--brand-500) 50%, var(--bg-body)), color-mix(in oklch, var(--brand-500) 75%, var(--bg-body))),
      "contrast": var(--white),
    ),
  ),
);
```

`$colors` generates the steps from `--brand-025` to `--brand-975`. See [Color]([[docsref:/customize/color#customizing]]). Pass every role of `"primary"`, because a partial map drops the other roles. See [Theme color map]([[docsref:/customize/sass#theme-color-map]]). An override of `$blue` also changes `primary`, but it changes every blue utility too.

### Theme colors

Each `$theme-colors` entry is a map of roles. Nested theme maps merge one level deep, so pass every role of a color you change, as in [Brand colors](#brand-colors). v6 has no `light` and `dark` theme colors: use the neutral `$theme-bgs` and `$theme-fgs` steps, color modes, or `inverse`.

| v5 Sass variable | v6 | Notes |
| --- | --- | --- |

| `$theme-colors-bg-subtle` | Removed, use `$theme-colors: <color> → bg-subtle` | Each theme color’s map now holds its own roles. |
