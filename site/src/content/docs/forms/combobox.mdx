## Overview

The combobox component provides a styled select experience using standard HTML markup. Pair an editable input or a [toggle button]([[docsref:/forms/combobox#button-examples]]) with a `.menu` overlay. Combobox is markup-first: you write the control and menu items in HTML, and Bootstrap handles filtering, keyboard navigation, selection, and form submission.

- Custom menu item content, including icons, descriptions, badges, and images
- Live filtering as you type in the field or in a button’s menu search input
- Optional check marks for selected items
- Single and multiple selection, with removable chips for multiple values in the editable field
- Optional free entry for values outside the menu
- Keyboard navigation for suggestions, with shortcuts for selecting and removing chips
- Form submission through generated or provided hidden inputs, with one entry per selected value in multiple mode
- Bubbling `input` and `change` events when a selection changes

## Example

Add `data-bs-toggle="combobox"` to a `.combobox` wrapper with a `.combobox-input` inside. Place a `.menu` after the wrapper, and give each selectable `.menu-item` a `data-bs-value`.

Type in the input to filter the options. The input keeps focus while the arrow keys highlight suggestions. Press <kbd>Enter</kbd> to commit a highlighted option. Typing alone does not select it.

<Example code={`<label for="editableLanguage">Language</label>
<div class="combobox" data-bs-toggle="combobox" data-bs-name="language">
  <input class="form-control combobox-input" id="editableLanguage" placeholder="Choose a language">
</div>
<div class="menu" aria-label="Languages">
  <button class="menu-item" type="button" data-bs-value="en">English</button>
  <button class="menu-item" type="button" data-bs-value="fr">French</button>
  <button class="menu-item" type="button" data-bs-value="ja">Japanese</button>
</div>`} />

We set the input’s combobox attributes and the listbox option IDs. Give the input an accessible name with a label. Keep the query input unnamed; `data-bs-name` names the submitted backing fields. Editing a selected single value clears its committed value until you select an option again.

## Multiple selections as chips

Use `.combobox-control` for a wrapping field and add `data-bs-multiple="true"`. The input uses `.form-ghost` to share the field with selected chips. Remove buttons include the option’s name. An empty multiple selection submits no entries.

<Example code={`<label for="editableInterests">Interests</label>
<div class="combobox-control" data-bs-toggle="combobox"
     data-bs-name="interests" data-bs-multiple="true">
  <input class="form-ghost combobox-input" id="editableInterests" placeholder="Add an interest">
</div>
<div class="menu" aria-label="Interests">
  <button class="menu-item" type="button" data-bs-value="design">Design</button>
  <button class="menu-item" type="button" data-bs-value="art,music">Art, music</button>
  <button class="menu-item" type="button" data-bs-value="engineering">Engineering</button>
</div>`} />

Selecting an option clears the query and keeps the editor ready for another search. The chips use the existing [chip styles]([[docsref:/components/chips]]). The menu remains the source of option identity and submitted values.

## Free-entry values

Set `data-bs-allow-custom="true"` to accept values outside the option list. Press <kbd>Enter</kbd> to commit the text. A popup is optional for a field with no predefined options; we create one when needed. We render value labels as text.

<Example code={`<label for="editableTags">Tags</label>
<div class="combobox-control" data-bs-toggle="combobox"
     data-bs-name="tags" data-bs-multiple="true" data-bs-allow-custom="true">
  <input class="form-ghost combobox-input" id="editableTags" placeholder="Type a tag and press Enter">
</div>`} />

Commas remain part of a value by default. Set `separator` explicitly to split typed or pasted values. `createOnBlur` is off by default so moving focus does not commit unfinished text. `maxItems` limits committed multiple selections. Repeated free-entry strings reuse an existing option rather than creating another chip.

## Editor keyboard behavior

- <kbd>↑</kbd> and <kbd>↓</kbd> highlight available suggestions while focus stays in the input.
- <kbd>Enter</kbd> commits the active suggestion, or the query when free entry is enabled.
- <kbd>Escape</kbd> closes the popup. <kbd>Tab</kbd> leaves the field without selecting a suggestion.
- With an empty query, <kbd>Backspace</kbd> or <kbd>Delete</kbd> focuses and highlights the last enabled chip. Press either key on a chip to remove the highlighted chips.
- Horizontal arrow keys move between chips in the field’s direction. Hold <kbd>Shift</kbd> to extend or shrink a range from its anchor. <kbd>Home</kbd> selects the first chip; <kbd>Shift+End</kbd> extends to the last. Plain <kbd>End</kbd> or <kbd>Escape</kbd> clears the chip highlight and returns to the editor.
- Click a chip to highlight it. Use <kbd>Ctrl</kbd> or <kbd>Cmd</kbd> while clicking to toggle individual highlights, or <kbd>Shift</kbd> to select a range.
- <kbd>Ctrl+A</kbd> or <kbd>Cmd+A</kbd> selects all enabled chips when a chip has focus or the query is empty. With query text, the input keeps native text selection.

Chip highlights use the filled `.active` style. Focusing a chip or tabbing to its remove button also highlights the chip. They select values for a removal action; they do not change submitted values. Returning to the input clears these highlights. Bulk removal emits one committed change and honors each option’s cancelable removal event.

Input-method composition takes precedence over component shortcuts. Removable chips also provide named buttons for direct keyboard access. Check the complete multiple-value interaction with your supported browsers and assistive technologies before release.

## Form submission

The combobox creates a hidden `<input>` for form submission when `data-bs-name` is set on the wrapper or button. The hidden input’s `name` matches the attribute value and its `value` updates whenever the selection changes.

```html
<!-- What you write -->
<label for="countryPickerInput">Country</label>
<div id="countryPicker" class="combobox" data-bs-toggle="combobox" data-bs-name="country">
  <input class="form-control combobox-input" id="countryPickerInput">
</div>
<div class="menu">...</div>

<!-- What the JS creates (inserted before the wrapper) -->
<input type="hidden" name="country" value="us">
```

For multiple selection, each selected option submits a separate field with the same name. For example, selecting `us` and `ca` submits `countries=us&countries=ca`. Values that contain commas remain unchanged. If your server requires brackets, use `data-bs-name="countries[]"`; we copy the name as written.

The first hidden input remains in the DOM so event listeners keep a stable target. It holds the first submitted value. Additional inputs hold the remaining values in menu order. With no multiple selection, the first input is disabled and no values are submitted. Single selection keeps one field, empty when no option is selected.

```js
const form = document.querySelector('#preferences')
const selectedCountries = new FormData(form).getAll('countries')
```

### Use an existing input

Set `data-bs-input` to the selector of a hidden input, or pass the element as the `input` option. We use that field’s name and form owner. The `name` option applies only to automatically created fields.

```html
<input type="hidden" id="comboboxCountryValue" name="country">
<label for="comboboxBoundCountry">Country</label>
<div class="combobox" data-bs-toggle="combobox" data-bs-input="#comboboxCountryValue">
  <input class="form-control combobox-input" id="comboboxBoundCountry">
</div>
<div class="menu" aria-label="Countries">
  <button class="menu-item selected" type="button" data-bs-value="us" role="option" aria-selected="true">United States</button>
  <button class="menu-item" type="button" data-bs-value="ca" role="option" aria-selected="false">Canada</button>
</div>
```

Mark the initial selection with `.selected` on the options. We sync the field from that markup; an existing field value does not select an option. Use an explicit selector for each component, even when several rows use the same field name. We do not infer a binding from neighboring elements or shared names.

Calling `dispose()` keeps a provided input, its current first value, and its application attributes. It removes generated inputs and component listeners. In multiple mode, generated fields for the other values are also removed. One provided input cannot preserve the entire repeated-value payload after disposal.

### Disabled state, reset, and updates

A disabled input or button does not submit its generated fields. Provided inputs keep their own disabled setting. Generated fields follow the input or button’s `form` attribute, including forms outside the component’s parent.

Resetting the form restores the initial option selection, label, and submitted values. Preventing the form’s `reset` event cancels that change. Initialization, reset, and `update()` do not emit selection-change events.

We observe disabled and form-attribute changes. Call `update()` when you move the component or change its selected option markup. Also call it before reading `FormData` or submitting to a new form in the same task as an attribute change:

```js
const picker = document.querySelector('#countryPicker')
const input = picker.querySelector('input')
const combobox = bootstrap.Combobox.getInstance(picker)

input.disabled = true
combobox.update()
const data = new FormData(input.form)
```

Normal form submission also synchronizes the fields before submission. If you replace the entire menu element, dispose the component and initialize it again. Applications own asynchronous option loading.

Hidden inputs do not participate in native constraint validation. Preserving attributes for an application validator does not add native `required` or `pattern` validation.

Menu controls the show and hide transitions. Combobox forwards its lifecycle events, including outside-click dismissal. Cancel `show.bs.combobox` or `hide.bs.combobox` to prevent that action. Await `show()` or `hide()` for transition completion.

Combobox owns the Menu instance registered on its input or button. Let Combobox create and dispose that instance. Do not replace or dispose the Menu separately.

### Events

Component events fire on the component root: the wrapper for an editable field, or the button. Query input events remain native input events; they do not commit a value. When selection changes, we first update the label and all submitted fields. We then dispatch bubbling `input` and `change` events from the stable hidden input, followed by `change.bs.combobox` on the root. Without a backing field, the plain events also fire on the root.

Selecting the same single option again does not emit a change. Selecting a different option with the same value does. Read all multiple values from `event.value` on the component event or `FormData.getAll(name)`, rather than the first hidden input’s value.

<BsTable>
| Event | Description |
| --- | --- |
| `add.bs.combobox` | Fires before an option is selected. Cancel it to prevent selection. Has `value` and `item` properties. |
| `remove.bs.combobox` | Fires before a selected option is removed. Cancel it to keep that value. Has `value` and `item` properties. |
| `show.bs.combobox` | Fires immediately when the `show` method is called. |
| `shown.bs.combobox` | Fires when the menu has been made visible. |
| `hide.bs.combobox` | Fires immediately when the `hide` method is called. |
| `hidden.bs.combobox` | Fires when the menu has been hidden. |
| `select.bs.combobox` | Fires after chip highlights change. Contains `selected` values and their option `items`. Does not change form values. |
| `change.bs.combobox` | Fires after selection changes. The event has `value` and `item` properties. `value` is an array in multiple mode. |
</BsTable>

## Accessibility

Give the input a visible label. We set its `role="combobox"`, connect it to the listbox, and update `aria-expanded` as the menu opens and closes. The input retains focus while you navigate suggestions with the arrow keys.

For a button that opens a listbox, give the button `aria-haspopup="listbox"` and `aria-expanded="false"`. Set `role="listbox"` on the menu and use `role="option"` and `aria-selected` on its options. Use `disabled` on unavailable option buttons.
